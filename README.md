[## Баланс / История операций — как это устроено и как чинить](#)

### Как работает история операций в боте
* Пользователь нажимает «💰 Баланс» → видит кнопку «📊 История операций».
* Клавиатура истории:
  * `📊 1 день` → `operations_history_1`
  * `📊 7 дней (Excel)` → `operations_history_7`
  * `📊 30 дней (Excel)` → `operations_history_30`
  * `⬅️ Назад` → `operations_back`
* Хендлеры:
  * `operations_history` показывает меню с периодами.
  * `operations_history_1` выводит текстовую историю за день.
  * `operations_history_7` и `_30` формируют Excel-файл и возвращают ту же клавиатуру.
  * `operations_back` делает `callback_payment_menu`, возвращая пользователя в главное меню баланса.

### Как обрабатывается `is_premium`
* `users.is_premium` в БД — `NOT NULL`, хранит `True/False`.
* Сервис `BillingService.get_or_create_user` нормализует любые входные значения из Telegram в `bool`.
* Дополнительный предохранитель на уровне SQLAlchemy `engine.before_cursor_execute`: при `UPDATE users` и параметре `is_premium=None` он принудительно ставит `False` и пишет предупреждение вида `ENGINE PATCH: users.id=... had is_premium=None before UPDATE, forcing False`.

### Что делать при изменениях клавиатур / моделей
* Меню Баланса/Истории:
  * не удалять старые callback’ы одновременно с добавлением новых — оставляйте legacy-обработчики, которые переводят пользователя на актуальный экран;
  * не убирать поддержку старых `callback_data`, пока явно не убеждены, что в чатах не осталось старых сообщений.
* Модели пользователя:
  * не допускать `is_premium=None` в `UPDATE`;
  * при добавлении новых флагов заранее думайте о значениях по умолчанию и миграциях.

### Мини-чек-лист при проблемах с Балансом / Историей / `is_premium`
1. Проверить логи:
   ```bash
   cd /opt/media-lab/deploy
   docker logs deploy-bot-1 --since 10m | grep -i "NotNullViolation\|ENGINE PATCH" -n || echo "нет NotNullViolation/ENGINE PATCH за 10 минут"
   ```
2. Проверить кнопку «История операций» и «Назад»:
   * "💰 Баланс" → "📊 История операций" → "📊 1 день" → "⬅️ Назад"
   * Убедиться, что сообщение не содержит «❌ Произошла ошибка…»
3. Если менялся код:
   * перезапустить бота:
     ```bash
     cd /opt/media-lab/deploy
     docker compose -f docker-compose.prod.yml up -d bot
     ```
   * проверить, что `../app:/app/app` смонтирован — код в контейнере совпадает с репозиторием.

### ✨ **Ретушь** — Деликатная ретушь лица

Профессиональная ретушь портретов с сохранением естественности.

**Режимы:**
- **Мягкая ретушь** (`fal-ai/retoucher`)
  - Удаляет мелкие дефекты (прыщи, пятна)
  - Выравнивает тон кожи
  - Сохраняет естественную текстуру и поры
  - Не изменяет структуру лица
  
- **Усилить черты** (`fal-ai/bytedance/seedream/v4.5/edit`)
  - Улучшает четкость черт лица и кожи
  - Слегка улучшает яркость глаз
  - Сохраняет структуру лица, пропорции и возраст
  - **Не изменяет губы** — оставляет их без изменений
  - **Не омолаживает** — сохраняет исходный возраст
  - **Не добавляет новые объекты** — только улучшает существующие черты

**Процесс:**
1. Нажмите "✨ Ретушь"
2. Отправьте фото лица (как фото или документ, до 10 МБ)
3. Выберите режим: "Мягкая ретушь" или "Усилить черты"
4. (Опционально) Укажите дополнительную инструкцию:
   - Примеры для "Мягкая ретушь": "убери прыщи на лбу", "сделай кожу более гладкой", "убери темные круги под глазами"
   - Примеры для "Усилить черты": "улучши четкость черт", "сделай кожу более гладкой"
5. Или нажмите "Пропустить" для автоматической ретуши
6. Получите отретушированное изображение

**Ограничения:**
- Максимальный размер файла: 10 МБ
- Модели не изменяют структуру лица — только улучшают качество и убирают дефекты
- Режим "Усилить черты" не изменяет возраст, губы и не добавляет новые объекты

## 🔧 Технические детали

### Асинхронная обработка

Все длительные операции выполняются асинхронно через **queue API** с polling:
- Генерация изображений
- Изменение изображений (Smart Merge/Edit)
- Ретушь
- Face Swap (базовая модель и WaveSpeed Face Swap)
- Upscale

Это обеспечивает надежную обработку без блокировки бота и возможность обработки больших файлов.

### Форматы и размеры файлов

- **Генерация**: PNG формат, автоматическая оптимизация размера
- **Редактирование**: PNG формат
  - Автоматическое сжатие изображений больше 4 МБ для соответствия лимитам API (10 МБ после base64)
  - Сжатие применяется только при необходимости, сохраняя качество маленьких файлов
- **Изменить**: PNG формат, 1024×1024px по умолчанию (для Nano Banana Pro можно выбрать формат)
  - Автоматическое сжатие больших изображений перед отправкой
- **Ретушь**: PNG формат, максимальный входной файл 10 МБ
- **Upscale**: PNG формат, увеличение в 2 раза

### Автоматическое сжатие изображений

Бот автоматически сжимает изображения перед отправкой в API, если их размер превышает лимиты:
- **Порог сжатия**: 4 МБ (до base64 кодирования)
- **Лимит API**: 10 МБ после base64 кодирования
- **Метод**: JPEG сжатие с постепенным снижением качества (85→50) и, при необходимости, уменьшение размера изображения
- **Результат**: Изображения меньше 4 МБ не сжимаются, сохраняя максимальное качество

### Сохранение результатов

- Все результаты сохраняются локально в `media/`:
  - `media/images/` — сгенерированные изображения
  - `media/edits/` — отредактированные изображения, ретушь, face swap, upscale
- Бот автоматически отправляет результат пользователю
- Файлы доступны для последующего использования (кнопка "Редактировать" под результатом)

## 💰 Система биллинга и баланса

### Бизнес-логика

**Начальный баланс:**
- При регистрации каждому пользователю начисляется **30₽** (3000 копеек) на баланс
- Баланс хранится в **копейках** для точности расчетов (без округлений)
- Все расчеты выполняются в копейках для исключения проблем с округлением

**Списание средств:**
- Средства списываются только после успешного завершения операции
- Операция создается со статусом `PENDING` при резервировании
- После успешного выполнения операция переводится в статус `CHARGED` и списывается баланс
- При ошибке операция переводится в статус `FAILED` без списания средств

**Промокоды:**
- 🎟️ **WELCOME10** — скидка 10% на все операции
- 🎟️ **SAVE20** — скидка 20% на все операции
- 🎟️ **BONUS30** — скидка 30% на все операции
- 🎟️ **FREE_ACCESS** — бесплатный доступ (все операции бесплатны)
- Промокоды активируются через меню "💰 Баланс" → "🎟️ Промокод для операций"
- Скидка применяется ко всем операциям до отмены
- Можно отменить промокод в любой момент

**История операций:**
- Все операции сохраняются в базе данных
- В истории отображается время в московском часовом поясе (Мск, UTC+3)
- Отображается информация о примененной скидке (если была)
- Доступна через кнопку "💰 Баланс" → "📊 История операций"

**Пополнение баланса:**
- Команда `/add_balance <amount>` для администраторов (в рублях)
- Пример: `/add_balance 500` — пополнит баланс на 500₽ (50000 копеек)

**Экспорт статистики:**
- Команда `/export_stats` для получения Excel файла с детальной статистикой
- Все даты и время отображаются в московском часовом поясе (UTC+3)
- Включает: пользователей, операции по типам, использованные модели, статистику по дням/неделям/месяцам, вопросы ИИ-помощнику
- Автоконцилиация платежей: свежие `pending` (20 с – 12 ч) проверяются каждые 20 с, более старые проходят единичную проверку и при отсутствии явного `canceled/expired` помечаются как `stale` (повторная попытка не чаще раза в сутки). В `canceled` переводим только по явному ответу YooKassa.
- Если reconcile уже зачислил платеж, повторные команды `/start payment_<id>` или `/check_payment` показывают сообщение «оплата уже была зачислена» без повторного пополнения и без второго уведомления.

### Проверка автозачисления платежей
1. Создать платеж через меню «💰 Баланс», оплатить и **не** возвращаться в бот.
2. В течение одной минуты открыть «💰 Баланс» — сумма пополнения уже должна быть учтена автоматически.
3. Выполнить `/check_payment`: баланс не меняется повторно, повторное начисление не происходит.
4. После автозачисления выполните `/start payment_<id>` или `/check_payment` ещё раз — бот ответит «оплата уже была зачислена», без повторных списаний или дублей уведомлений.

### База данных (PostgreSQL)

**Архитектура:**
- Используется **PostgreSQL 16** в Docker контейнере
- База данных: `media_lab`
- Пользователь: `media_lab_user`
- Connection pooling: 10 соединений + 20 overflow

**Конфигурация:**
```yaml
# deploy/docker-compose.prod.yml
postgres:
  image: postgres:16-alpine
  environment:
    POSTGRES_DB: media_lab
    POSTGRES_USER: media_lab_user
    POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-media_lab_password_change_me}
  volumes:
    - postgres_data:/var/lib/postgresql/data

bot:
  environment:
    - DATABASE_URL=postgresql://media_lab_user:${POSTGRES_PASSWORD}@postgres:5432/media_lab
  volumes:
    - ../scripts:/app/scripts  # Монтирование scripts для экспорта статистики
```

**Преимущества PostgreSQL:**
- ✅ Поддержка высокой нагрузки (200+ пользователей, готовность к масштабированию)
- ✅ max_connections: 300 (достаточно для 200+ пользователей)
- ✅ Одновременные записи без блокировок
- ✅ Connection pooling для эффективного использования соединений
- ✅ Надежное хранение данных с персистентными томами
- ✅ Оптимизация autovacuum для поддержания производительности

**Структура таблиц:**
- `users` — пользователи (telegram_id, has_free_access, operation_discount_code_id, operation_discount_percent)
- `balances` — балансы пользователей (user_id, balance в копейках, тип: BigInteger)
- `operations` — операции (user_id, type, price в копейках, status, discount_percent, created_at, task_id)
  - Статусы: `PENDING`, `CHARGED`, `FREE`, `FAILED`
- `discount_codes` — промокоды (code, discount_percent, max_uses, current_uses, is_active)
- `user_discount_codes` — использование промокодов пользователями
- `payments` — платежи через YooKassa (подготовлено, не реализовано)
- `user_statistics` — агрегированная статистика пользователей

**Миграция с SQLite:**
- Проект был мигрирован с SQLite на PostgreSQL для поддержки высокой нагрузки
- Баланс переведен на хранение в копейках (BigInteger) для исключения округлений
- Все существующие данные были перенесены в PostgreSQL

**Важно:**
- Для production измените `POSTGRES_PASSWORD` в `.env` файле
- Все воркеры подключаются к PostgreSQL через `127.0.0.1:5432`
- Бот подключается к PostgreSQL через Docker network (имя сервиса `postgres`)

## 🧹 Очистка Docker

Docker может занимать много места на диске из-за старых образов, build cache и остановленных контейнеров.

### Быстрая очистка

#### Безопасный режим (рекомендуется, по умолчанию):
```powershell
cd docker
.\cleanup-docker.ps1
```

Или через BAT файл:
```cmd
cd docker
cleanup-docker.bat
```

Скрипт безопасно удалит:
- Неиспользуемые образы (dangling и неиспользуемые)
- Build cache
- Остановленные контейнеры
- Неиспользуемые сети
- **Volumes НЕ удаляются** (безопасный режим по умолчанию)
- **Папка `media/` НЕ очищается** (по умолчанию)

**Важно:**
- **Работающие контейнеры и их образы будут сохранены** - можно запускать даже когда Docker и бот работают!
- **Bind mounts (`../media:/app/media`) НЕ удаляются** - это папки на хосте
- Данные в папке `media/` остаются нетронутыми (по умолчанию)
- Удаляются ТОЛЬКО остановленные контейнеры и неиспользуемые образы

#### Очистка с удалением данных в `media/`:

Если вы хотите также удалить содержимое папки `media/` (изображения, видео и т.д.):

```powershell
cd docker
.\cleanup-docker.ps1 -CleanMedia
```

Или используйте специальный скрипт:
```cmd
cd docker
cleanup-docker-with-media.bat
```

**⚠ ВНИМАНИЕ:** Это удалит все файлы в папке `media/` (images, videos, edits, face_swap и т.д.). Действие необратимо!

### Автоматическая очистка

Настройте автоматическую очистку через Планировщик задач Windows (рекомендуется раз в неделю).  
Подробная инструкция: [`docker/DOCKER_CLEANUP_README.md`](docker/DOCKER_CLEANUP_README.md)

## ❓ FAQ

### Почему нет изображения?
Проверьте логи воркера — возможно, выбранная модель временно отключена (например, ответ «Temporarily disabled…»). Попробуйте другую кнопку или `model=...`.

### Как задать свою модель?
Отправьте `Изображение <промпт> | model=имя`. Алиасы (`dalle3`, `flash`, `flux`) поддерживаются.

### Как изменить размер?
Через клавиатуру выбирайте вертикальный, квадратный или горизонтальный формат. Для тонкой настройки всё ещё можно передать `| size=1024x1024` вручную.

### Как изменить изображение?
Нажмите `✏️ Изменить`, выберите модель, загрузите изображение (или до 4 изображений) и опишите желаемые изменения. Модели поддерживают добавление объектов, объединение изображений, удаление элементов и изменение сцены. После получения результата, при необходимости, нажмите `⬆️ Улучшить`, чтобы увеличить изображение.

### Как работает ретушь?
Выберите режим: **Мягкая ретушь** для удаления дефектов и выравнивания тона кожи, или **Усилить черты** для улучшения четкости черт лица. Можно указать дополнительную инструкцию (например, "убери прыщи на лбу") или пропустить для автоматической ретуши. Модели не изменяют структуру лица — только улучшают качество.

### Как работает кнопка "Изменить"?
Отправьте до 4 изображений (или одно для редактирования), выберите модель, опишите желаемые изменения. Модель может объединить изображения, добавить объекты, удалить элементы или изменить сцену. 
- **Nano Banana Pro** и **Nano-Banana**: можно писать промпт на русском языке
- **Seedream**: промпт автоматически переводится на английский язык
Можно добавить текст, указав его в описании изменений.

### Как работает кнопка "Написать"?
Кнопка "✍️ Написать" использует LLM (Claude 3.5 Sonnet) для генерации детальных промптов без противоречий. Просто опишите желаемое изображение простыми словами, и получите структурированный промпт, готовый для использования в кнопке "🎨 Создать". Промпт проверяется на логическую согласованность и избегает двойных трактовок.

### Где итоговые файлы?
По умолчанию в `media/images` и `media/edits` (монты через docker compose). Бот также отправляет документ в Telegram.

### Почему Upscale возвращает WebP вместо PNG?
Модель `fal-ai/recraft/upscale/crisp` может возвращать WebP формат независимо от запрашиваемого формата. Результат сохраняется в том формате, который возвращает API.

### Почему файл после Upscale маленький (185 КБ)?
Если скачивание не удалось, файл отправляется по URL. Telegram может сжать его. Бот пытается скачать файл локально для гарантии качества, но если это не удается, отправляет по URL.

### Поддерживает ли бот русский язык?
Да! Модели **Nano Banana Pro** и **Nano-banana** полностью поддерживают русский язык:
- При создании изображений через "🎨 Создать" → "Nano Banana Pro" или "Nano-banana"
- При объединении изображений через "🔗 Объединить" → "Nano-Banana (Merge)"
- При генерации промптов через "✍️ Написать" — промпты создаются на русском языке
Промпт можно писать на русском языке без перевода. Для других моделей (Seedream) промпт автоматически переводится на английский язык.

### Что делать, если изображение слишком большое?
Бот автоматически сжимает изображения больше 4 МБ перед отправкой в API. Сжатие применяется только при необходимости и не влияет на качество маленьких файлов. Если вы видите сообщение об ошибке размера файла, попробуйте уменьшить разрешение изображения перед загрузкой.

## 👥 Многопользовательский режим

### ✅ Возможности

Бот **поддерживает многопользовательский режим** и может использоваться несколькими пользователями одновременно.

**Лимиты fal.ai API:**
- **20 concurrent tasks** на один API ключ (по всем endpoint'ам) - текущий лимит
- Лимит применяется ко всем пользователям бота, использующим один API ключ
- Текущее использование: 0/20 (0%)
- Пиковое использование за 30 дней: 3/20 (15%)
- Для enterprise клиентов можно увеличить лимиты (связаться с fal.ai)

**Рекомендации для многопользовательского использования:**

1. **Один API ключ для всех пользователей:**
   - Все пользователи бота используют один общий API ключ
   - Лимит в 10 concurrent tasks распределяется между всеми пользователями
   - При превышении лимита запросы автоматически ставятся в очередь

2. **Мониторинг использования:**
   - Используйте Platform APIs fal.ai для отслеживания использования
   - Настройте уведомления при достижении лимита concurrent requests
   - Отслеживайте использование через dashboard: `https://fal.ai/dashboard`

3. **Для больших нагрузок:**
   - Свяжитесь с fal.ai для увеличения лимитов (enterprise план)
   - Рассмотрите возможность использования нескольких API ключей с балансировкой нагрузки
   - Используйте queue API для надежной обработки запросов (уже реализовано в боте)

**Текущая архитектура бота:**
- ✅ Асинхронная обработка через queue API — запросы не блокируются
- ✅ Автоматическая очередь при превышении лимитов
- ✅ Один API ключ может обслуживать множество пользователей
- ✅ Все операции выполняются через воркеры (RQ), что позволяет обрабатывать запросы параллельно

**Ограничения:**
- Максимум 20 одновременных задач на один API ключ (текущий лимит)
- При большом количестве пользователей (100+) запросы могут ставиться в очередь

## 🔧 Технические детали базы данных

### SQLite в многоконтейнерной среде

**Проблема:**
При использовании нескольких контейнеров (bot, worker-image, worker-image-2, worker-image-3) с `network_mode: host` и относительными путями к SQLite, каждый контейнер создавал свой файл базы данных, что приводило к рассинхронизации данных.

**Решение:**
1. **Общий файл базы данных:**
   - Используется абсолютный путь: `/tmp/media_lab_shared.db`
   - Файл монтируется через bind mount во все контейнеры

2. **Синхронизация после операций:**
   ```python
   # После reserve_operation и confirm_operation
   import shutil
   db_path = db.bind.url.database.replace("sqlite:///", "")
   shared_db_path = "/tmp/media_lab_shared.db"
   if db_path != shared_db_path and os.path.exists(db_path):
       shutil.copy2(db_path, shared_db_path)
   ```

3. **Конфигурация Docker Compose:**
   ```yaml
   volumes:
     - /tmp/media_lab_shared.db:/tmp/media_lab_shared.db:rw
   
   environment:
     - DATABASE_URL=sqlite:////tmp/media_lab_shared.db
   ```

**Результат:**
- Все контейнеры используют один и тот же файл базы данных
- Изменения видны сразу во всех контейнерах
- Нет рассинхронизации данных между bot и worker'ами
